# 03 语言模型与交叉熵：makemore 第 1 部分（bigram）
 
来源：Andrej Karpathy，[The spelled-out intro to language modeling: building makemore](https://www.youtube.com/watch?v=PaCmpygFfXo)（Neural Networks: Zero to Hero 第 2 课），代码见 [karpathy/makemore](https://github.com/karpathy/makemore)。
 
## 一句话总结
 
同一个 bigram 字符级语言模型，先用"数数"训练，再用神经网络加梯度下降训练，两者用同一个损失（NLL）评价，结果几乎一样。神经网络的价值不在这节课的效果，而在于可以扩展：logits → softmax → NLL → 梯度下降这套流程，一直沿用到 GPT。
 
## 1. 任务
 
- 数据：32,033 个英文名字。
- 目标：生成"像名字但不在名单里"的新名字。
- 做法：一次生成一个字母，每一步只看前一个字母、猜下一个，这叫 bigram（二元）模型。
- 符号：26 个字母，加上 `.` 表示名字的开头和结尾，共 27 个。
 
## 2. 计数法：数出一张概率表
 
1. **拆成字母对。** `emma` 前后加上 `.`，拆成 `.→e`、`e→m`、`m→m`、`m→a`、`a→.` 共 5 对。全部名字一共 228,146 对。
2. **数次数。** 做一张 27×27 的表 $N$，行是当前字母，列是下一个字母，每遇到一对就在对应格子加 1。
3. **变成概率。** 每个格子除以本行总数，每行加起来等于 1。第 m 行就是 $P(\text{下一个字母} \mid \text{当前是 m})$。
4. **采样生成。** 从 `.` 开始，按那一行的概率抽一个字母，再按新字母那一行继续抽，抽到 `.` 停止。
 
生成的名字质量很差，因为只看前一个字母，但比随机乱抽好得多。GPT 生成文本也是这样一个 token 一个 token 地往外抽，叫自回归。
 
## 3. 损失函数：负对数似然（NLL）
 
好模型应该给训练数据里真实出现的"下一个字母"分配高概率。
 
```math
\text{NLL} = -\frac{1}{N}\sum_{i=1}^{N} \log p(y_i \mid x_i)
```
 
其中 $x_i$ 是当前字母，$y_i$ 是正确的下一个字母，$N$ 是样本数。
 
推导思路：
 
1. 把所有正确答案的概率乘起来，得到似然，越大越好；
2. 22 万个小于 1 的数相乘会小到无法计算，所以取 log，乘法变加法（log 单调，最大化乘积等于最大化 log 之和）；
3. 加负号并取平均，变成越小越好的损失。
 
−log 的惩罚力度：
 
| 给正确答案的概率 $p$ | 损失 $-\ln p$ |
| --- | --- |
| 1 | 0 |
| 0.5 | 0.69 |
| 0.01 | 4.61 |
| → 0 | → ∞ |
 
模型越笃定地猜错，罚得越重。
 
参考数字：
 
| 情况 | 平均 NLL |
| --- | --- |
| 均匀瞎猜，每个字母 1/27 | $\ln 27 \approx 3.30$ |
| 神经网络随机初始化 | 约 3.77 |
| 计数法 bigram | 约 2.45 |
| 神经网络训练后 | 约 2.46 |
| 完美模型 | 0 |
 
和统计的联系：最小化 NLL 就是最大似然估计（MLE）；当正确答案只有一个时，NLL 就是交叉熵损失。GPT 预训练用的也是它。
 
## 4. 平滑
 
问题：训练数据里没出现过的组合（比如 `jq`）概率为 0，$-\log 0 = \infty$，损失直接爆掉。
 
办法：每个格子先加假计数再归一化。以 q 那一行为例，假设数据里 q 后面只出现过 u，共 50 次：
 
| 做法 | q→u 的概率 | q→其他每个字母 |
| --- | --- | --- |
| 不加 | 100% | 0 |
| 每格加 1 | 66% | 1.3% |
| 每格加 1000 | 3.9% | 3.7%（接近均匀的 1/27） |
 
假计数越多，分布越接近均匀，模型越保守。统计上叫拉普拉斯平滑。
 
## 5. 神经网络法：把同一张表学出来
 
1. **训练数据。** 写成"输入 → 答案"：输入 `. e m m a`，答案 `e m m a .`。文本自带答案，不需要人工标注，这叫自监督。
2. **one-hot。** 不能直接输入编号（m = 13 并不比 e = 5 "大"），所以每个字母变成一个长度 27、只有自己位置为 1 的向量。
3. **一层网络。** 27×27 的权重矩阵 $W$，随机初始化，没有偏置、没有激活函数。one-hot 乘 $W$ 得到 27 个打分，叫 logits，可正可负。
4. **softmax。** 把打分变成概率：
 
```math
p_j = \frac{e^{z_j}}{\sum_{k=1}^{27} e^{z_k}}
```
 
可以把 logits 理解成"计数的对数"：取 exp 还原成正的"计数"，再归一化成概率，和计数法第 3 步是同一件事。小例子：
 
| | A | B | C |
| --- | --- | --- | --- |
| logits | 2 | 0 | −1 |
| exp | 7.39 | 1 | 0.37 |
| 概率 | 0.84 | 0.11 | 0.04 |
 
5. **训练循环。** 和 micrograd（笔记 02）完全一样：前向算损失 → 梯度清零 → 反向传播求 $W$ 的梯度 → 沿梯度反方向更新 $W$。视频里在全部 22.8 万对样本上用学习率 50，损失从约 3.77 降到约 2.46。
6. **结果。** 和计数法几乎一样，生成的名字也一样。
 
## 6. 两个关键结论
 
### 6.1 one-hot 乘 W，就是取 W 的一行
 
one-hot 只有一个位置是 1，相乘时其他行都被乘成 0。输入 b = [0, 1, 0] 时：
 
```math
[0,1,0]\begin{bmatrix}1&2&3\\4&5&6\\7&8&9\end{bmatrix} = [4,5,6]
```
 
推论：
 
- $W$ 的每一行对应一个当前字母，存的是"它后面每个字母的打分"；
- 每一行只被以这个字母开头的样本训练，和计数表的每一行一一对应；
- 训练完后，每一行近似等于 $\log N$ 的对应行（差一个常数），神经网络学到的就是那张计数表。
 
这就是 embedding 的来源：既然乘 one-hot 等于查一行，后面就直接按编号查表。
 
### 6.2 平滑等于正则化
 
- $W$ 全为 0 时，所有 logits 相同，softmax 后正好是均匀分布；
- 所以把 $W$ 往 0 拉，就等于往均匀分布拉，效果和加假计数一样。
 
```math
L = \text{NLL} + \lambda \cdot \frac{1}{27^2}\sum_{i,j} W_{ij}^2
```
 
NLL 想贴合数据，惩罚项像弹簧把 $W$ 拉回 0，两者拉扯。$\lambda$ 越大，相当于假计数越多，越接近均匀（视频用 $\lambda = 0.01$）。这就是 L2 正则化，统计里的岭回归，大模型训练里叫 weight decay。
 
## 7. 为什么要用神经网络
 
结果一样，是因为两者参数规模相同（27×27）、目标相同（最小化 NLL）、信息相同（只看前一个字母）。区别类似 OLS：一个直接套公式求解析解（多项分布的 MLE 就是频率），一个用梯度下降逼近，最后停在同一个答案。
 
但计数法扩展不了：
 
- 看前 $n$ 个字母，表格有 $27^n$ 行、$27^{n+1}$ 格。$n = 3$ 时约 2 万行、53 万格，22.8 万对数据根本填不满；
- 格子之间互相独立，见过 `ann` 也推不出 `enn`。类比"分组求均值"：组分得越细，空组越多。
 
神经网络更像回归模型，用有限的参数拟合规律，能推断没见过的组合。
 
后面从 MLP 到 RNN 再到 Transformer，变的只是 logits 怎么算出来；logits → softmax → NLL → 梯度下降这条链不变。

## 我的疑问与解答
 
**Q1：前半段不是神经网络吧？**
不是。前半段是纯统计：数次数、归一化，没有需要学的参数，也没有梯度下降。"模型"是要解决的问题（给前文预测下一个字），神经网络只是实现它的一种方式。前半段的意义是先把问题和评分标准（NLL）讲清楚。
 
**Q2：为什么完全瞎猜的损失是 ln 27？**
瞎猜时每个字母都是 1/27，不管正确答案是哪个，它都只分到 1/27，所以每个样本的损失都是 $-\ln(1/27) = \ln 27$。一堆相同的数取平均还是它自己，约等于 3.30。用自然对数是因为 PyTorch 默认以 e 为底。
 
**Q3：随机初始化的 W 损失约 3.77，为什么比瞎猜还差？**
随机 W 不等于均匀分布，它会随机偏向某些字母，给一部分正确答案的概率低于 1/27。−log 对"笃定地猜错"罚得很重，所以平均下来比均匀瞎猜更差。
 
**Q4：两种方法为什么结果一样？**
参数规模、目标函数、可用信息都一样，最优解只有一个。计数法直接算出最优解（频率就是 MLE），梯度下降一步步走到同一个点，类似 OLS 用公式求解和用梯度下降求解得到同一个系数。
 
**Q5：看前 3 个字母，为什么是 53 万格而不是 27³？**
$27^3 \approx 2$ 万是行数（前文有多少种组合），每一行还有 27 列（下一个字母的 27 种可能），所以格子数是 $27^4 \approx 53$ 万。
 
**Q6：广播（broadcasting）是什么？**
两个形状不同的数组做运算时，PyTorch 会把小的那个自动"复制拉伸"成和大的一样的形状。27×27 的表除以 27×1 的"每行总数"，这一列会被横向复制 27 份，每行除以自己的总数。坑在 keepdim：求和时没保留维度会得到形状 (27,)，它会被当成一行去广播，变成按列归一化，程序不报错但结果全错。
 
**Q7：为什么要 one-hot，不能直接输入编号？**
网络内部做的是乘法和加法，编号会被当成有大小的数量，但字母之间只有"是不是同一个"的区别，没有大小关系。
